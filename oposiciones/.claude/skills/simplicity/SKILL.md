# Simplicity is the ultimate sophistication

Every screen in Tesón should show the fewest elements that still let the student do the one thing that screen is for. When in doubt, remove. This rule comes from Kyle's reviews and outranks completeness, cleverness and "nice to have".

## The three things Tesón is

Every element must serve at least one of these. If it serves none, remove it.

| Pillar | What it means on screen |
|---|---|
| **Personalizado** | The student's own level, plan and weak points, from their own answers |
| **Adaptativo** | The next questions change with each answer: weak concepts first, spaced review of mistakes |
| **Explicaciones visuales** | Every answer explained with "La clave", one highlight, and a scheme or chart where one helps |

## The test for every element

Before adding or keeping anything (button, line of text, card, badge, chart, dialog, setting), ask:

1. **What is this screen for?** Name its single job in a few words.
2. **Does this element help that job right now?** If not, remove it, or move it behind a tap.
3. **Would the student miss it if it were gone?** If not, it goes.
4. **Is it explaining something the student didn't ask about?** Formulas, methodology and "how we calculate" notes don't belong on the main path.
5. **Is it repeating something already on screen?** Say it once.

## Rules

- **One primary action per screen.** Secondary actions are quiet (ghost buttons or links). Never three equal buttons fighting each other.
- **Show the result, not the method.** Show "6,3 / 10", not the penalty formula.
- **Progressive disclosure.** Details live one tap away: area → its concepts; question → its explanation; settings collapsed under "Ajustes y cuenta".
- **No confirmation dialogs** unless the action loses work, like submitting with blank answers or deleting an account.
- **Symbols over words** when the symbol is universal: ← → for back and next, ✓ ✗ for right and wrong.
- **No boxes around everything.** Use plain text, a dot or a single highlight; a border is a last resort.
- **Phrases, not sentences.** "Diputación Permanente: mínimo 21 miembros". The explanation explains; the visual anchors.
- **Lists only show what's active.** Hide empty or not-yet-started rows behind a count ("12 conceptos sin practicar").
- **Ask at the moment of value.** Ask for the email after the diagnostic shows a result, never before. Never ask for an opinion right after a diagnostic.
- **One highlight per explanation.** Mark the decisive words and nothing else.
- **Charts earn their place.** Use one only when a picture says it faster than a line of text (composition, thresholds, proportions). Follow the dataviz skill for colours.

## What Kyle has already removed (don't bring these back)

| Removed | Instead |
|---|---|
| "Salir" and "Impugnar" in the test top bar | Exit is under pause; report is inside the explanation |
| Bordered boxes around question numbers | Plain numbers; the current one gets a filled dot |
| "Anterior" / "Siguiente" | ← → |
| "¿Entregar?" confirmation when everything is answered | Submits directly; still asks if blanks remain |
| Penalty formula on results | Score and time only |
| Fortalezas / Áreas a mejorar and the opinion prompt on diagnostic results | One email card: "Conoce tus puntos fuertes y débiles" |
| 60-row concept table, confusions list and test history on Progreso | One bar per area; tap for concepts, practice and schemes |

## Before you finish

- Count the elements on the screen before and after your change. The count should not go up without a reason Kyle would accept.
- Take a phone-width (390px) screenshot and look at it. If your eye doesn't know where to go first, there is too much.
- If you added something, say in one line what you removed or why nothing could go.
